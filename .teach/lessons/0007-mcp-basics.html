MCP 基础 — agent 如何"长出工具"

约 15 分钟 · 前置：无（你在 butterfly 里已用过 MCP 客户端——本课补协议骨架，并站到 NAP 的"服务器侧"视角）· 产出：说清 MCP 的三个动作和"宿主是中间人"的结构

前六课的 K8s 基础件解决的是"agent 住在哪、怎么活"；这最后一课解决"agent 怎么获得能力"。模型本体只会一件事：读文本、产文本。它能查数据库、建沙箱、发消息，靠的都是外部工具——而 MCP（Model Context Protocol，模型上下文协议）就是连接 agent 与工具的标准化插座。

名字来历与身世：Model Context Protocol，Anthropic 于 2024 年底开源的协议，迅速成为行业事实标准（OpenAI、Google、微软相继宣布支持）。类比：USB 之于外设——任何人按接口造设备（工具服务器），任何电脑（agent 宿主）都能插上就用，不用一对接线。你在 butterfly 的 mcp/ 模块里已经是"插座的使用侧"。

协议就三个动作

① initialize（握手）客户端与服务器互相亮身份和能力："我支持这些功能版本，你呢？"——对上暗号才继续
② tools/list（发现）客户端问"你有哪些工具？"，得到清单：每个工具的名字、给模型看的描述、参数的 JSON Schema
③ tools/call（调用）客户端发"调用工具 X，参数 Y"，服务器执行后返回结果

协议里还有 resources（给模型读的资源）和 prompts（预置提示模板）两样，目前生态的主力是 tools——本课只盯主力。

最关键的认知：模型从不直接连 MCP 服务器

这张结构图是本课的核心，也是很多初学者的盲区——中间有一个宿主（host/client），所有 MCP 通信都经过它：

① 宿主启动时：连接各个 MCP 服务器 → 握手 → 拿回工具清单
② 对话时：宿主把工具清单以文本形式放进模型的上下文（"你有这些工具可用：……"）
③ 模型决策：模型输出的仍然是文本——"我想调用 create_sandbox，参数 image=python:3.12"
④ 宿主执行：宿主解析这句话 → 真正发起 MCP 调用 → 服务器干活 → 结果文本回给模型
⑤ 模型继续：模型读到结果，决定下一步——循环

也就是说：模型对工具的全部"知识"就是清单里那段描述文本；模型的全部"调用"就是一段结构化的意图输出。真正跑腿的是宿主。这个结构和你在 butterfly 引擎里实现的 turn 循环（provider 装配 → 工具表注入 → 解析工具调用 → 执行回填）是同一个形状。

传输方式：两种

传输形态典型场景
stdioMCP 服务器作为宿主本机的一个子进程，走标准输入输出本地工具（文件操作、本地搜索）
Streamable HTTPMCP 服务器是个 HTTP 服务，远程可达平台化工具、SaaS 集成

记住这张表的原因：它决定了"工具离 agent 多远"。NAP 的平台工具全是第二种——工具服务器住在 control-plane 里，agent pod 远程调用（中间还有 pod 内一跳 mcp-forward，下面马上看）。

NAP 的用法（轻量预告，细节在钻探课）

NAP 把整套平台中间件做成了 MCP 工具服务器——control-plane 就是那个服务器（control-plane/src/mcp/tools.ts），一次性注册八个工具族：

memory记忆存取sandbox建沙箱、跑命令、取文件
agentagent 互相调用browser远程浏览器
skills技能管理AFS跨 agent 共享目录
export_file_url铸公开分享链接builder-mode搭建模式

而 agent 那一侧的配置不直连 control-plane，指向 pod 内的一个转发层（mcp-forward）：agent CLI 的配置里不含任何凭证，转发层出站时才附上 token。为什么这么绕、token 怎么反解出会话上下文、工具集怎么按请求定制——这是钻探课"控制反转与 MCP 中转"的主题，此处只立路标。

检索练习

1. 谁真正和 MCP 服务器建立连接、收发协议消息？
  1. 模型本身直连
  2. 用户的浏览器
  3. 宿主程序居中
  4. 数据库的代理
2. tools/list 返回的清单里，模型认识一个工具靠什么？
  1. 服务器的源代码
  2. 名字加描述文本
  3. 网络端口与地址
  4. 官方注册的证书
3. 模型"调用"一个工具时，它实际输出的是什么？
  1. 直接执行的代码
  2. 一次网络的数据包
  3. 数据库里的语句
  4. 结构化的意图文本
4. MCP 的握手（initialize）发生在什么时候？
  1. 宿主连接服务器时
  2. 模型每次回复前
  3. 用户发消息之后
  4. 工具执行完成时
5. NAP 里扮演 MCP 服务器（提供工具）的是谁？
  1. agent pod 自己
  2. control-plane 一侧
  3. 用户的浏览器
  4. 外部的镜像仓库
6. stdio 和 Streamable HTTP 两种传输的本质区别是？
  1. 速度的快与慢
  2. 收费与免费之别
  3. 加密方式的不同
  4. 工具离得近或远
