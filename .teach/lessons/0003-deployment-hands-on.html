Deployment 流转实验 —— 亲手看它怎么用、怎么转

约 40 分钟（含课前阅读）· 前置：第 1、2 课 · 产出：亲眼见过一次完整的"声明 → 收敛 → 扩缩 → 自愈 → 滚动升级 → 回滚"，第 4 课的所有概念都有实物可对照

第 4 课要讲 Deployment 与 StatefulSet 的概念对比，但概念课直接上容易晕。这一课先让你在真实的集群上把 Deployment 完整玩一遍——第 2 课讲的"期望状态、收敛、自愈"全都变成你亲手触发、亲眼看到的东西。做完再回第 4 课，每一个名词都有对应的记忆画面。

  • 中文系统教程：guangzhengli《Kubernetes 教程》——从 Container 讲到 Pod、Deployment、Service 的中文动手教程，本地环境用 minikube（与本课一致）。课前重点读它的 Deployment 章：YAML 逐字段讲解，删除 pod 后自愈的命令输出直接贴出，与本课实验一一对应。
  • 动手材料：官方中文教程「Hello Minikube」——从启动 minikube 到创建 Deployment、暴露 Service 的完整走一遍，与本课实验环境完全一致。
  • 概念材料：官方中文文档「Deployment」——重点读用例、创建 Deployment、更新 Deployment（含滚动升级）三节，其余跳过。
  • 补充材料：Jimmy Song《Kubernetes Handbook》——中文开源书稿，适合换一个角度复述。

准备环境（5 分钟）

如果你还没有实验集群，用 k3d 创建一个（它就是在 Docker 里跑 k3s——NAP 快速启动用的同一个内核；用完 k3d cluster delete nap-demo 即可销毁）：

curl -sL https://raw.githubusercontent.com/k3d-io/k3d/main/install.sh | bash k3d cluster create nap-demo kubectl get nodes # 看到一个 Ready 的节点即成功

前置条件：Docker（docker version 正常）。没有的话先装 Docker Desktop 或 OrbStack 的官方 dmg（Intel Mac 别用 brew 装，已无预编译包）。习惯 minikube 的也可以用它，命令对照见下方表格——但推荐 k3d：与 NAP 自部署的运行时同源。

minikube 和第 2 课的 k3s、另一个常见工具 k3d 是什么关系？三者都是"本地实验集群"方案：minikube 在 VM 或 Docker 里跑标准 K8s，老牌、中文教程围绕它的材料最多；k3s 是轻量版 K8s 发行版（第 2 课主角，NAP 自部署用的就是它）；k3d 则是把 k3s 装进 Docker 里跑的工具，创建销毁更快。三者的 kubectl 与实验命令完全一致，本课程实验用哪个都行——默认 minikube。

k3s 和标准 K8s 内核有区别吗？API 层面零区别：k3s 通过了 CNCF 一致性认证，kubectl 和所有清单行为完全相同；差异只在打包——单二进制、默认 SQLite 替代 etcd、内置 flannel/Traefik。所以用 k3d 也能跟 minikube 系的教程（比如课前阅读的 guangzhengli 教程），只需替换少数专属命令：

教程里的 minikube 命令k3d 等价命令
minikube startk3d cluster create k8s
minikube deletek3d cluster delete k8s
eval $(minikube docker-env)（让本地 build 的镜像进集群）不需要切环境：正常 docker build 后执行 k3d image import 镜像名:tag
minikube image load xxxk3d image import xxx（自建镜像必须先导入，否则 ImagePullBackOff）
minikube service xxxkubectl port-forward svc/xxx 8080:80
minikube dashboard无内置，跳过

六个实验

实验 1 · 创建：声明"我要两个"
kubectl create deployment web --image=nginx:1.27 --replicas=2 kubectl get deployment web kubectl get pods --show-labels
你应该看到：两个 pod，名字形如 web-5d8f7c-xxa2v——带随机尾巴（你从来没有给 pod 起过名）；READY 列从 0/2 变成 2/2（收敛过程）；--show-labels 显示每个 pod 都带着 app=web 这枚标签。
概念绑定：你只声明了"2 个副本"，名字是系统起的；标签是按模子盖上去的章——第 4 课"三个名字"辨析的实物。
实验 2 · 扩容：改账本
kubectl scale deployment web --replicas=4 kubectl get pods -w
你应该看到：多出两个新名字的 pod 陆续出现，最终 4 个 Running。按 Ctrl+C 退出观察。
概念绑定：scale 改的是期望值（2 → 4），新 pod 是 controller 数出缺口后补的——第 2 课循环的手动版。
实验 3 · 自愈：删掉一个看看
kubectl delete pod web-xxxxx # 换成你自己的某个 pod 名 kubectl get pods -w kubectl get deployment web
你应该看到：被删的 pod 消失，一个新的（又是新名字）很快补上；而 deployment 的输出里 replicas 相关字段自始至终没变过。
概念绑定：期望从未改变，是现实被拉了回去。"没有报警-修复，只有循环"——这句话现在是你的亲眼所见。
实验 4 · 滚动升级：新旧交替
kubectl set image deployment web nginx=nginx:1.28 kubectl rollout status deployment web kubectl get pods
你应该看到：rollout status 逐条打印升级进度；结束后 get pods 里出现了一批按新模子造的新 pod，旧的逐步消失。过程中新旧 pod 是共存交替的（先起新的、再删旧的），不是先全删再重建。
概念绑定：滚动升级是 Deployment 的内置能力，"服务不中断"的机制就藏在这个交替节奏里——第 4 课的正式内容。
实验 5 · 回滚：退回上一版
kubectl rollout history deployment web kubectl rollout undo deployment web kubectl rollout history deployment web
你应该看到：历史里至少两个版本记录；undo 之后回到 1.27。
概念绑定：回滚不是"特殊操作"，也是一次"改账本"——把期望指回旧版本，让循环再收敛一次。声明式的红利。
实验 6 · 标签认领：selector 的实物
kubectl get pods -l app=web kubectl describe deployment web | grep -A 2 "Selector"
你应该看到：用 -l app=web 查到的正是 Deployment 管的那批 pod；describe 里显示的 Selector 正是 app=web——两者对上了。
概念绑定：controller 数副本数时"数的就是这个查询的结果"。第 4 课讲"认领标准"时，回看这一步。
