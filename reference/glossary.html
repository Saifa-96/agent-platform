NAP 平台术语表

全课程共用。课程正文一律遵守此处的定义；术语有歧义时以本表为准。锚点为仓库内真实路径。

基础件（K8s 世界的基本砖块，从零教起）

镜像 container image
只读的打包模板：代码 + 运行时 + 依赖，分层叠加冻结而成。国纸：建房的围纸，自己不运行。
容器 container
镜像的一次运行实例：被内核隔离的进程（独立的文件系统视图、资源限额）。房子：按国纸建出来的一次实例。
Pod
K8s 的最小调度单位：一个或多个容器的组合，同 pod 容器共享网络（互见 localhost）和存储卷。NAP 的 agent 就住在一个 pod 里。
internal/k8s-provider/workspace-spec.ts
节点 node
一台worker 机器（物理机或 VM），pod 被调度到节点上运行。公寓楼的某一层。
sidecar
同 pod 里陪伴主容器的辅助容器。名字来历：摩托车边斗——绑在主车旁、随主车走、自己不是司机。NAP 的 workspace pod 里：agent 主容器 + AFS sidecar + memory sidecar。
internal/k8s-provider/workspace-spec.ts
/etc
Linux 系统配置文件的惯例目录：用户表、hosts、fstab、ssh 配置都在这。来历：最早是 et cetera（杂物间），后读作 Editable Text Configuration。体现“配置 = 纯文本文件”的 Unix 哲学。etcd 的名字 = 分布式版 /etc。
挂载 mount / /mnt
把另一块存储（磁盘/网络文件系统/数据库）接到目录树的某个位置，接好后用起来和本地文件夹一样。/mnt 是 Linux 惯例的挂载点目录，NAP 的共享盘、记忆库都挂在 /mnt/ 下。
FUSE
用户态文件系统：把“别处的东西”（网络存储、数据库）伪装成本地目录的技术。AFS sidecar 和 memory sidecar 的底层。
/workspace
NAP 约定的 agent 主工作目录：持久盘的挂载点，所有产出文件和 agent 的 HOME（.home）都在这。pod 死它不死。
Deployment
工作负载控制器之一：副本无名、等价、可互换，内置滚动升级与回滚。适合无状态服务。名字来历："一次部署"的名词化。NAP 的 static workspace 用单副本 Deployment。
internal/k8s-provider/static-workload.ts
StatefulSet
工作负载控制器之二：副本有稳定序号（db-0/1/2）、有序启停、通常各挂自己的盘。适合有状态服务（数据库）。名字来历：stateful（有状态）+ set。NAP 的 auto-scaling 创造性挪用：只要稳定身份做会话亲和，不要独立盘（所有副本共享一块 RWX 卷）。
internal/k8s-provider/auto-scaling-workload.ts
API server
K8s control plane 的唯一入口：所有读写都经它，期望状态记在它身后的 etcd。物业前台。
etcd
分布式键值库，存着整个集群的"期望 + 现状"账本。名字来历：分布式版的 /etc。物业的记账本。
kubelet
每台节点上各一个的代理，真正启动容器的角色：读到"这个 pod 归我管"就拉镜像、起进程。名字来历：little kube，小管家。注意它不做副本数决策——那是 workload controller 的事，两者只靠账本协作。
manifest（清单）
K8s 对象的声明文件（通常 YAML，本质 JSON）： Deployment、Service、PVC 都是"写一份清单 + apply（或代码直接提交）"。YAML 只是给人写的格式，程序可直接构造对象（NAP 即如此）。
kubectl
K8s 的命令行客户端：把清单/命令发给 API server。kubectl apply -f x.yaml = 提交一份声明。
workload controller（Deployment / StatefulSet）
住在 control plane 的软件循环：数副本数量，缺了就在账本里登记新 pod 对象（纯记账，不碰容器）。与 kubelet 是两层不同的循环——controller 管数量，kubelet 管执行。
scheduler
control plane 组件：给每个新 pod 对象挑一台机器，写进账本。总部派单员。
Service
一张稳定的虚拟门牌（不是"服务"本身）：VIP + DNS 名 + 自动维护的 pod 转报名单（按 label selector 认领，只含 Ready 的 pod）。名字来历：暴露"服务"的稳定入口。NAP static workspace 用 ClusterIP Service 寻址。
headless Service
clusterIP: None 的 Service：无 VIP，DNS 直接返回各 pod 地址；配合 StatefulSet 给每个副本稳定的带序号 DNS 名（db-0.xxx）。NAP auto-scaling 用它做会话亲和的精确路由。名字来历：没有 VIP 这颗"头"。
VIP / ClusterIP
Virtual IP：Service 分配的稳定虚拟 IP，请求到它后被轮询分给名单里的 pod。多副本 + 有状态会话时轮询会破坏亲和，这是 NAP auto-scaling 弃用它的原因。
CoreDNS
跑在集群里的域名解析服务，照着账本实时回答 pod/Service 地址查询。
session affinity（会话亲和）
同一会话的连续请求路由到同一副本。正在执行的 turn 现场只在一个副本的进程内存里，所以 auto-scaling 用 headless per-ordinal DNS 逐副本精确投递。
k3s
轻量版 K8s 发行版：单个二进制、内置 SQLite 替代 etcd，一台机器就能跑。NAP 的 quick start 用它把整套平台装进一台 Linux 机。
README.md Quick start、self-host/install.sh
K8s control plane（K8s 控制面）
集群的“物业”：保存期望状态、监控现实、不断把现实拉回期望。注意与 NAP 的 control-plane（平台服务）区分——后者是前者之上的一层应用。

世界（谁在跑）

control-plane
NAP 的核心服务（专名，不译）：核心 API + 编排器，管 workspace、session、凭据、放置决策。PostgreSQL 持久化。注意与下条“K8s control plane”区分。
control-plane/src/
工作区 workspace
一个 agent 实例的完整宿主单元：pod + PVC + 配置 + 会话集。平台多租户的隔离边界——不是用户，不是 session，是 workspace。
control-plane/src/services/db/workspaces.ts
env-runner
在 K8s 集群里干活的手臂：接收控制面的期望状态，收敛成真实的 Deployment/StatefulSet/PVC。可跑在远程集群，反向拨隧道回 control-plane（BYOI）。NAP 对应实现：env-runner-k8s。
env-runner-k8s/src/
agent core
可插拔的前沿 agent 引擎（Claude Code / Codex / Goose）。平台不写引擎，只适配。每个 core 通过同一个 ACP 适配器接入。
agents/*/src/、internal/acp-adapter/
副本 replica
auto-scaling workspace 的一个 pod 实例，按序号（ordinal）编址。多副本共享同一 PVC。
control-plane/src/services/replica-router.ts

一次对话（时间单位）

会话 session
连续多轮对话的载体。真身在 PostgreSQL（由 SSE 拦截器实时写入），不在 pod——所以断线、换副本、pod 死都不丢。
control-plane/src/services/chat/executeChat.ts
回合 turn
一条用户消息引发的完整 agent 执行。平台的基本调度单位：每 session 同时只允许一个 turn（租约），每 workspace 有并发容量门。
control-plane/src/services/chat/turn-gate.ts
SSE 拦截器 createInterceptedSSEResponse
agent 的流式响应穿过控制面时被"劫持"：持久化消息、写统计、广播给重连客户端。平台能看到一切的原因。
control-plane/src/lib/sse.ts
session token（会话令牌）
随 turn 铸造的短期令牌。MCP 请求带上它，控制面反解出 workspace/session/task 上下文——工具拿到“我是谁”的唯一途径。
control-plane/src/lib/session-token.ts

两种服务形状（钱与延迟的交易）

static serving（静态常驻）
固定单副本 Deployment，常驻不管有没有人用。延迟最低，成本固定。用 ClusterIP Service 寻址。
internal/k8s-provider/static-workload.ts
auto-scaling（自动伸缩）
StatefulSet + 共享 RWX PVC，副本跟 turn 需求走，可缩到零。下一条消息冷启动唤醒（90 秒预算）。用 headless Service 的 per-ordinal DNS 寻址——不用 VIP，因为轮询会破坏会话亲和。
internal/k8s-provider/auto-scaling-workload.ts、control-plane/src/lib/workspace-address.ts
idle GC
连续 N 天无活动的 workspace 被缩容。可逆——只回收 CPU/内存，PVC 和会话都在。
control-plane/src/services/idle-workspace-gc.ts

数据放哪（生死边界）

PVC（PersistentVolumeClaim）
持久卷声明：pod 向集群“申请一块盘”的凭据。每 workspace 一个，默认 10Gi，只增不减。/workspace 全部内容的物理宿主，独立于 pod 生死。NFS StorageClass 供给。
internal/k8s-provider/support.ts: workspacePvcName()
RWO / RWX ReadWriteOnce / ReadWriteMany
卷的访问模式。RWO：同一时刻只一台机器（节点）可挂载——限制单位是机器不是 pod，同机多 pod 可共享。RWX：多机同时挂同一卷（NFS 支持；块设备不行，两个内核同写一个文件系统会坏）。auto-scaling 多副本可能落在不同机器，所以必须 RWX。
PV（PersistentVolume）
provisioner 真实创建的存储资源，记录数据真身的地址（如 NFS 服务器+子目录）。pod 搬到哪台机器，那台机器的 kubelet 照 PV 地址去挂——数据不动。
StorageClass
供货规则：PVC 申请单走哪条供应链（NFS/云盘/CephFS），背后是 provisioner（供货商程序）。创建后烙死在 PVC 上不能换；访问模式（RWO/RWX）是它的能力。
provisioner
看 PVC 申请单发货的程序：创建 PV 并绑定。NAP 自部署用 nfs-subdir-external-provisioner；reclaimPolicy=Delete + archiveOnDelete=true（删 PVC 归档不立刻抹）。名字来历：供货商。
dufs
pod 内的轻量文件服务器（:8000），把 /workspace 以 HTTP 暴露。用户文件面板、下载、分享 URL 都经它——不是第二份拷贝，是视图。
agents/*/src/index.ts
AFS（Agent File System）
NAP 自建的跨 agent 文件系统：集群级共享卷 + FUSE 挂载到 /mnt/afs。agent 之间传大文件的通道：share_folder → grant_access，二进制不进对话上下文。
control-plane/src/mcp/tools/afs.ts
沙箱 sandbox
独立集群（OpenSandbox）里的按需容器，跑重活（编译/渲染）。默认 1 小时自毁，易失是特性：产物必须显式拉回 /workspace 才存活。
control-plane/src/mcp/tools/sandbox.ts

能力怎么到达 agent（缝）

MCP Model Context Protocol
工具协议。NAP 把平台中间件（沙箱/浏览器/记忆/AFS/agent 互调）全部做成 MCP 工具，按请求注册给 agent 的 core。
control-plane/src/mcp/tools.ts
mcp-forward（MCP 转发层）
pod 内的一跳：agent CLI 的 MCP 配置指向它，它出站时才附上凭证。core 配置里零 secret。
internal/mcp-forward/
ACP Agent Client Protocol
Zed 主导的 agent↔客户端协议。NAP 用一个适配器把三种前沿 core 包成同一种 server 形状——"引擎可插拔"的实现载体。
internal/acp-adapter/
channel（通道）
外部世界进平台的入口之一：Web UI、聊天渠道、HTTP API、webhook、定时。全部汇入同一条 chat 通道。
channel-gateway/、scheduler/
控制反转 desired state / control inversion
控制面只记录期望状态（"这个 workspace 应该在跑"），env-runner 收敛现实。平台的核心编排哲学。
control-plane/src/services/workspace-reconcile.ts
